Information

Process Discovery

The Discovery section is probably the first one every user interacts with. Through it, users can carry out the discovery process using the appropriate form. Its fields are:

Field Description
Name The name you want to assign to the execution.
Optimization Method Select the optimization algorithm to use. Available options are the evolutionary algorithms NSGAII, NSGAIII, and SPEA2.
Miner Type Select the process discovery algorithm to use. Available options are the Heuristic Miner and Inductive Miner.
Event Log The log that contains event information used in the discovery process. Only logs uploaded by the user to the application will be listed.
Evaluation Metrics This field allows the user to select the metrics used to evaluate the results of the discovery process. Currently, two metrics are implemented, but basic ones are recommended.
Hyperparameters Each optimization algorithm has its own hyperparameters. When an optimizer is selected, a dropdown will appear to specify the desired values, which will vary depending on the chosen optimizer.

Evaluation Metrics

These define how the discovered models are evaluated and are used throughout the optimization process to refine results. All metrics are set to minimize. Below are the implemented metrics.

All discovered models are Petri nets. An example image is shown below. More information is available on this page.

Basic Metrics

Metric Description
n places Number of places (circles in the Petri net) represented.
n transitions Number of transitions (rectangles in the Petri net) represented.
n arcs Number of arcs connecting places and transitions.
cycl complx Cyclomatic complexity measures the number of independent paths in a network, inspired by flow graph theory in software complexity.
ratio Place-to-transition ratio.
joins A join occurs when multiple places connect to a transition. This metric counts how often it happens.
splits A split occurs when a transition connects to multiple places. This metric counts how often it happens.

Usability metrics differ slightly. While the solutions are still evaluated as in basic metrics, the usability metrics add rules or constraints to the models. If a model breaks one of these rules, it is considered not useful and is penalized accordingly.

Usability Metrics

Metric Description
IS AP Whether the graph is aperiodic or not.
NSFE Total number of outgoing event flows.
GM Difference between incoming and outgoing flows.

Solutions

  • At the end of the discovery process, a table will be displayed showing most execution details. Clicking on 'Explore Solutions' will open a new page with all the optimizer's solutions.
  • The number of solutions depends on the population size set for the optimizer. For example, if set to 100, there will be 100 individuals (solutions) evolved into something useful.
  • For each solution, Variables and Objectives are displayed:
    • Variables: The hyperparameters used by the selected miner to generate the solution.
    • Objectives: The evaluation metric values. When using basic metrics, there will be 7 fields showing these values.
  • Each individual solution includes an image of the discovered Petri net, the result of running the mining algorithm with the specified hyperparameters (its variables).

Pareto Front

Although we may have as many solutions as individuals in the population, only a few will be the best. From a mathematical (metric) perspective, the best solutions are the non-dominated solutions.

In multi-objective optimization, a solution is said to dominate another if it is better in at least one objective and at least equal in the rest. Therefore, the best solutions are those that are not dominated. This set of solutions is called the Pareto Front.

Besides filtering solutions that belong to the Pareto front, a chart will also be displayed showing the magnitude of each objective in the Pareto solutions, helping visualize the non-dominance between them.
